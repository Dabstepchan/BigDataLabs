# Часть 6: GPU vs CPU

**Выполнен трек A** (CPU): pandas против Polars и DuckDB на той же агрегации по ключу (`brand`, `event_type`): число событий, уникальные пользователи, выручка, средняя цена. Вход у всех инструментов одинаковый: очищенные данные в Parquet, срезы 100 МБ и 1 ГБ и полный месяц.

Треки B и C не выполнялись: в среде выполнения (Google Colab, 2 ядра, 12,7 ГБ RAM) NVIDIA GPU нет. В ноутбуке есть необязательный блок: если в среде есть NVIDIA GPU и cuDF, тот же код pandas запускается через `cudf.pandas` без изменений, иначе блок пропускается.

## Запуск

Все замеры делает ноутбук `../Lab_BigData_2.ipynb` (Часть 6). Каждый инструмент запускается в отдельном процессе:

```
python work/tasks.py pandas_parquet <список путей> <файл результата>
python work/tasks.py polars_parquet <список путей> <файл результата>
python work/tasks.py duckdb_parquet <список путей> <файл результата>
```

Время и пиковая память (RSS всего дерева процессов) снимаются через `psutil`, каждый срез запускается трижды, в таблицу идёт медиана.

## Замеры

| Инструмент | 100 МБ: время | 100 МБ: RAM | 1 ГБ: время | 1 ГБ: RAM | Полный: время | Полный: RAM |
|---|---|---|---|---|---|---|
| pandas | 2,0 с | 0,25 ГБ | 8,4 с | 1,06 ГБ | 35,3 с | 4,75 ГБ |
| Polars | 2,0 с | 0,28 ГБ | 3,3 с | 1,28 ГБ | 19,1 с | 6,34 ГБ |
| DuckDB | 1,4 с | 0,18 ГБ | 5,0 с | 0,50 ГБ | 21,4 с | 1,24 ГБ |

- Polars быстрее pandas на 2% на 100 МБ, на 61% на 1 ГБ и на 46% на полном датасете. DuckDB быстрее на 32%, 41% и 39%.
- На двух ядрах параллелизм даёт немного: Polars и DuckDB занимают 1,2-1,5 ядра против 0,96 у pandas. Основной выигрыш дают столбцы Arrow и векторизованная агрегация без объектов Python. DuckDB агрегирует поток данных и тратит меньше всех памяти.

## Когда GPU не окупается

Весь запрос по месяцу данных на CPU занимает 19-21 с в Polars и DuckDB, на 1 ГБ 3-5 с. Это меньше порога около 30 с на запрос, после которого окупается инициализация GPU (2-3 с). Узкое место здесь чтение данных, а не вычисления. GPU имеет смысл при десятках гигабайт и тяжёлых агрегациях, для одного месяца событий остаётся CPU-трек.
